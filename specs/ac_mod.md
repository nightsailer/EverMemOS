
# ac.mod.md 文件编写指南

你的目标是探索指定模块目录，然后根据阅读的代码后撰写.ac.mod.md模块文档。整个过程需要遵循项目标准并使用 `specs/jobs/todo-list-<module_name>.md` 记录工作进度。

## 任务概述

你需要为指定的模块创建或者更新 `.ac.mod.md` 文档，该文档应该帮助开发者快速理解和使用模块功能。文档将保存在 `specs/` 目录下，与模块源码分离管理。

**模块类型说明**：
- **包模块**：包含 `__init__.py` 的目录，可能有多个子模块
- **单文件模块**：单个 `.py` 文件，直接包含所有功能

## 工作执行步骤

### 步骤 1: 识别模块类型并深度探索

首先确定模块类型，然后使用对应的探索策略：

**包模块探索**：
- `list_dir(relative_workspace_path="[包路径]")` - 列出包目录内容
- `read_file(target_file="[包路径]/__init__.py")` - 读取包初始化文件
- `grep_search(query="class|def|import", include_pattern="[包路径]/*.py")` - 搜索包内代码定义
- `file_search(query="[包名]")` - 查找相关文件
- `codebase_search(query="What does [包名] package do?")` - 语义搜索了解包用途

**单文件模块探索**：
- `read_file(target_file="[文件路径].py")` - 读取完整文件内容
- `grep_search(query="class |def |^[A-Z_]+ =", include_pattern="[文件名].py")` - 搜索类、函数、常量定义
- `codebase_search(query="What does [文件名].py module do?")` - 语义搜索了解模块用途
- `grep_search(query="from [文件名]|import [文件名]")` - 查找使用示例

### 步骤 2: 分析核心功能

**包模块分析**：
- `read_file(target_file="[包路径]/[主要子模块].py")` - 读取主要子模块内容
- `grep_search(query="from [包路径]|import.*[包名]")` - 查找使用示例
- `grep_search(query="test.*[包名]", include_pattern="*test*.py")` - 查找测试文件
- `codebase_search(query="How is [包名] package used in the project?")` - 查找使用场景

**单文件模块分析**：
- 已在步骤1中完成文件内容读取
- `grep_search(query="from [文件名]|import.*[文件名]")` - 查找使用示例
- `codebase_search(query="How is [文件名] used in the project?")` - 查找使用场景
- `grep_search(query="test.*[文件名]", include_pattern="*test*.py")` - 查找测试文件

### 步骤 3: 编写文档内容

1. 根据识别的模块类型选择对应的文档模板
2. 使用 `edit_file` 工具在 `specs/[模块名称].ac.mod.md` 创建文档
3. 按照对应的标准结构逐章节编写
4. 每完成一个章节就使用 `todo_write` 更新工作进度
5. 确保所有路径引用正确

### 步骤 4: 依赖关系准确性验证

**重要提醒**：依赖关系必须基于实际代码分析，而非推测！

**验证对其他模块的依赖**：
- `grep_search(query="from [模块路径]|import.*[模块名]", include_pattern="*.py")` - 查找该模块的实际导入语句
- `read_file(target_file="[模块路径]/__init__.py")` - 检查模块的导入声明
- `codebase_search(query="What modules does [模块名] import?")` - 语义搜索导入关系

**验证被其他模块依赖的情况**：
- `grep_search(query="from [当前模块路径]|import.*[当前模块名]")` - 查找其他模块对该模块的导入
- `grep_search(query="[当前模块名]\\.", include_pattern="*.py")` - 查找对该模块的具体使用
- `codebase_search(query="Which modules use [当前模块名]?")` - 语义搜索使用关系

**验证具体使用场景**：
- `grep_search(query="[主要类名]|[主要函数名]", include_pattern="*.py")` - 查找具体的类和函数使用
- `codebase_search(query="How is [主要类名] used in the project?")` - 查找使用示例

**依赖关系文档要求**：
1. **必须基于实际代码**：所有依赖关系都必须有具体的代码引用支撑
2. **提供具体使用场景**：说明在什么情况下会使用这些依赖
3. **区分直接和间接依赖**：明确哪些是直接导入，哪些是间接依赖
4. **验证路径准确性**：确保所有引用的 specs 路径都存在对应的文档

### 步骤 5: 验证和完善 

使用以下工具验证文档质量：
- `run_terminal_cmd` - 验证代码示例可执行性
- `grep_search` - 检查依赖关系的准确性
- `codebase_search` - 确认文档完整性
- `read_file` - 检查其他相关 `.ac.mod.md` 文档的依赖关系描述

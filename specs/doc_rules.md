# 文档编写原则（强制）

## 对象：Claude Code（AI），非人类

**目标**: 信息等效前提下，极致节省 token

## 强制规则

### 1. 单一数据源（SSOT）
- ✅ 状态/进度 → 外部文件，动态读取
- ✅ 重复内容 → 引用，不复制
- ❌ 同一信息出现在多处

### 2. 紧凑格式
- ✅ 表格 > 列表 > 段落
- ✅ 符号 > 文字（✅❌→←⚠️📍）
- ✅ 缩写 > 全称（PR/DB/API）
- ❌ 修饰性语言（"请注意"、"让我们"）
- ❌ 解释性段落（直接指令）

### 3. 删除冗余
```markdown
❌ 删除：
- 示例中的注释
- 重复的说明
- "如下所示"、"例如"等过渡词
- 空行（除分隔符）
- 所有 emoji（除状态标记）
- 不必要的总结和进度报告

✅ 保留：
- 操作指令
- 必要数据
- 引用路径
- 状态标记（✅❌⏳）

⭐ 总结原则：
- ❌ 常规任务完成后不做总结
- ✅ 仅在以下情况总结：
  1. 用户明确要求总结
  2. 复杂多步骤任务完成（5+个主要步骤）
  3. 发现重要问题需要用户决策
  4. 里程碑/阶段性工作完成
```

### 4. 引用优于复制
```markdown
❌ 复制 200 行代码示例
✅ 引用: .claude/templates/service_template.py

❌ 列出所有 10 个原型文件
✅ 引用: req-spec/app-vue/src/views/*.vue

❌ 重复工作流说明
✅ 引用: specs/m2-milestones/git-worktree-workflow-v2.md
```

### 5. 命令式 > 描述式
```markdown
❌ "您可以通过执行以下命令来启动开发"
✅ "> /dev-next"

❌ "这个文件包含了所有的配置选项"
✅ "配置: config.yaml"
```

## 实施检查

**新建/更新文档前问自己**：
- [ ] 此信息是否已存在其他文档？→ 引用
- [ ] 能否用表格代替段落？→ 表格
- [ ] 能否用符号代替文字？→ 符号
- [ ] 是否有修饰性语言？→ 删除
- [ ] 是否有重复说明？→ 删除
- [ ] 能否缩短 50%？→ 继续精简
